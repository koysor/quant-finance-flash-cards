# Off-Policy vs On-Policy RL

**Topic:** Machine Learning
**Tags:** off-policy, on-policy, q-learning, sarsa, importance sampling, historical data, replay buffer
**Created:** 2026-06-06
**Author:** Claude Sonnet 4.6

## Definition

**On-policy** RL algorithms learn the value of the policy currently being executed — the behaviour policy and the target policy are the same. **Off-policy** algorithms learn the value of a target policy that differs from the behaviour policy used to collect data, enabling learning from historical datasets or replay buffers generated by a different (possibly random or human expert) policy. The distinction determines whether an RL agent can be trained on archived trade data or requires live market interaction.

## Key Formula

**On-policy TD target** (SARSA — evaluates the action actually taken):

$$Q(s_t, a_t) \leftarrow Q(s_t, a_t) + \alpha\left[r_{t+1} + \gamma\, Q(s_{t+1}, a_{t+1}) - Q(s_t, a_t)\right]$$

**Off-policy TD target** (Q-learning — evaluates the greedy action regardless of what was done):

$$Q(s_t, a_t) \leftarrow Q(s_t, a_t) + \alpha\left[r_{t+1} + \gamma \max_{a'} Q(s_{t+1}, a') - Q(s_t, a_t)\right]$$

**Importance sampling correction** (for general off-policy learning from behaviour policy $\mu$, learning target policy $\pi$):

$$G_t^{\text{IS}} = \prod_{k=t}^{T-1} \frac{\pi(a_k \mid s_k)}{\mu(a_k \mid s_k)} \cdot G_t$$

The product of density ratios $\rho_t = \pi(a_t|s_t)/\mu(a_t|s_t)$ re-weights the behaviour policy's returns to give unbiased estimates under the target policy.

**Key comparison:**

| Property | On-policy (SARSA, PPO) | Off-policy (Q-learning, DQN, SAC) |
|---|---|---|
| Data source | Current policy only | Any policy (replay buffer, logs) |
| Sample efficiency | Lower | Higher (reuses data) |
| Convergence | More stable | Can diverge with function approx |
| Finance use | Live paper trading | Historical trade log training |

## Example

**Execution agent trained on historical logs:** An investment bank has 3 years of VWAP execution logs from a rule-based algorithm. They want to train a RL hedging agent without disrupting live trading.

Off-policy (Q-learning): load the logs as $(s_t, a_t, r_t, s_{t+1})$ tuples into a replay buffer, train directly. The agent learns the optimal policy without generating new data — but since the behaviour policy (VWAP rule) is deterministic, importance weights $\rho_t = \pi(a_t)/\text{VWAP}(a_t)$ are infinite whenever $\pi$ would take a different action, requiring policy constraints.

On-policy (PPO): must run the RL agent live in a paper-trading environment to collect its own trajectories. More expensive to deploy, but avoids the distributional shift problem — the data always matches the current policy.

## Remember

The on-policy/off-policy distinction is the **most practically important RL design choice for finance**. Almost every real-world financial RL application starts with historical data — three years of order flow, hedging decisions, or execution logs — and off-policy methods (Q-learning, DQN, SAC) can exploit this directly. On-policy methods must generate new data by actually trading, which is expensive (capital at risk, market impact) and slow. However, off-policy learning from historical logs is dangerous when the **behaviour policy's action distribution is too narrow**: if the historical trader only ever sold between 9:30–10:00, the off-policy agent has no data on afternoon selling and may learn catastrophically wrong Q-values there. This is the **distributional shift** problem in offline RL — addressed by conservative Q-learning (CQL) and behaviour-regularised approaches that penalise Q-values for out-of-distribution actions.
